# P2PDraw

P2PDraw — застосунок для спільного векторного малювання в локальній мережі. Учасники з'єднуються напряму, тому центральний сервер не потрібен. Проєкт має графічні версії для Windows і Android.

## Можливості

- Малювання пензлем, лініями, прямокутниками й еліпсами.
- Переміщення, зміна розміру, дублювання та видалення об'єктів.
- Робота з шарами, скасування та повторення локальних дій.
- Спільне редагування документа через локальну мережу.
- Збереження документа та експорт у PNG і SVG.
- Пошук сесій у мережі або ручне підключення за IP-адресою та портом.

## Як влаштована система

### З'єднання між вузлами

P2PDraw використовує топологію **Full Mesh**: кожен вузол встановлює TCP-з'єднання з іншими учасниками тієї самої сесії. Центральний сервер для зберігання документа або пересилання операцій не використовується. Кожен вузол має власну копію документа та журнал операцій.

#### Виявлення вузлів

Для пошуку учасників у локальній мережі використовується UDP Multicast:

- вузол періодично надсилає `PeerId`, `SessionId`, TCP-порт і версію протоколу;
- інші вузли перевіряють оголошення та показують доступні сесії;
- IP-адреса береться з адреси відправника UDP-пакета;
- якщо Multicast недоступний, можна підключитися вручну за IP-адресою та TCP-портом.

Група Multicast — `239.255.51.10`, UDP-порт — `5100`. Оголошення надсилаються кожні 2 секунди. Вузли, від яких немає оголошень понад 8 секунд, прибираються зі списку.

#### Встановлення TCP-з'єднання

Під час початкового обміну вузли перевіряють `PeerId`, `SessionId` і `ProtocolVersion`. Після цього вони надсилають операції та виконують початкову синхронізацію. Інформація про відомі адреси допомагає учасникам встановити прямі з'єднання між собою. Якщо два вузли одночасно підключилися один до одного, напрямок з'єднання вибирається за `PeerId`, щоб залишилося одне TCP-з'єднання.

### Операції та синхронізація

Малюнок не передається як растрове зображення після кожної зміни. Вузли обмінюються операціями над векторним документом: створенням і продовженням штрихів, створенням фігур, переміщенням, зміною розміру, видаленням об'єктів та змінами шарів.

Кожна операція має:

- `OperationId` — унікальний ідентифікатор;
- `PeerId` — ідентифікатор автора;
- `SequenceNumber` — порядковий номер операції цього вузла;
- `LamportTime` — логічний час.

`OperationLog` зберігає операції, ігнорує повторний `OperationId` і перевіряє унікальність пари `PeerId + SequenceNumber`. Логічний годинник Лампорта оновлюється під час створення та отримання операцій. Для детермінованого порядку порівнюються `LamportTime`, `PeerId`, а потім `OperationId`. Це логічний порядок, а не фізичний час; сам по собі він не гарантує причинного порядку всіх подій.

### Видалення, конфлікти та відновлення

Видалені об'єкти залишають **tombstone** — позначку з їхнім ідентифікатором. Пізніша операція зі старим ідентифікатором не відновить видалений об'єкт; ідентифікатори не використовуються повторно.

Операції над об'єктом відтворюються в детермінованому порядку. Для переміщення та зміни розміру зберігається остання за міткою операція. Очищення полотна охоплює лише об'єкти, відомі вузлу в момент очищення, тому нові або ще невідомі об'єкти не видаляються.

Під час синхронізації вузли обмінюються ідентифікаторами відомих операцій і надсилають відсутні операції або Snapshot. Snapshot містить стан документа, журнал операцій, tombstones, шари та дані про незавершені штрихи. Він перевіряється й об'єднується з локальним станом. Після розриву з'єднання можна продовжувати редагування офлайн; після перепідключення вузли обмінюються пропущеними операціями.

## Структура рішення

```text
P2PDraw/
├── P2PDraw.sln
├── global.json
├── src/
│   ├── P2PDraw.Core/

│   │   ├── Operations/      # Операції та журнал
│   │   ├── Sync/            # SyncEngine, Lamport Clock, Snapshot
│   │   ├── Storage/         # Формат файлу проєкту
│   │   └── Export/          # Експорт SVG
│   ├── P2PDraw.Networking/
│   │   ├── Discovery/       # UDP Multicast Discovery
│   │   ├── Protocol/        # Повідомлення та TCP framing
│   │   └── Transport/       # TCP-з'єднання між вузлами
│   ├── P2PDraw.App/         # Спільний Avalonia-інтерфейс та логіка редактора
│   │   ├── Controls/        # Полотно
│   │   ├── Documents/       # Відкриття та збереження файлів
│   │   ├── Editing/         # Undo/Redo та дублювання
│   │   ├── Export/          # Експорт PNG
│   │   ├── Interaction/     # Введення, геометрія та навігація полотном
│   │   ├── Session/         # Сесії та керування з'єднаннями
│   │   ├── Styles/          # Стилі інтерфейсу
│   │   ├── ViewModels/      # Стан редактора
│   │   └── Views/           # Avalonia-подання
│   ├── P2PDraw.Desktop/     # Запуск Windows/Desktop
│   ├── P2PDraw.Android/     # Запуск Android
│   └── P2PDraw.Simulator/   # Консольний вузол для мережевих сценаріїв
└── tests/P2PDraw.Tests/
    ├── App/
    ├── Core/
    ├── Integration/
    └── Networking/
```

## Технології

- .NET 10 і C# 14.
- Avalonia UI 12.1.4.
- `System.Net.Sockets` для TCP та UDP.
- `System.Text.Json` для мережевих повідомлень.
- xUnit v3 для автоматичних тестів.
- Для Desktop потрібен .NET 10 SDK.
- Для Android додатково потрібні .NET Android workload, Android SDK з API 36 і сумісний JDK.

## Збірка та запуск

### Windows

```powershell
dotnet build src/P2PDraw.Desktop/P2PDraw.Desktop.csproj -c Release
dotnet run --project src/P2PDraw.Desktop/P2PDraw.Desktop.csproj -c Release --no-build
```

### Android

```powershell
$project = "src/P2PDraw.Android/P2PDraw.Android.csproj"
$apk = "src\P2PDraw.Android\bin\Release\net10.0-android36.0\android-arm64\publish\org.p2pdraw.app-Signed.apk"
$adb = "$env:AndroidSdkDirectory\platform-tools\adb.exe"
dotnet workload install android
dotnet build $project -t:InstallAndroidDependencies -f net10.0-android36.0 -p:AcceptAndroidSDKLicenses=True
dotnet publish $project -c Release -f net10.0-android36.0
& $adb install -r $apk
& $adb shell monkey -p org.p2pdraw.app 1
```

### Тести

```powershell
dotnet test tests/P2PDraw.Tests/P2PDraw.Tests.csproj -c Release
```

## Підключення учасників

### Через пошук сесій

1. Запустіть P2PDraw на обох пристроях і підключіть їх до однієї локальної мережі.
2. На першому пристрої відкрийте панель **Сесія** та натисніть **Створити сесію**.
3. На другому пристрої відкрийте **Сесія**, натисніть **Знайти сесії**, виберіть потрібну сесію та приєднайтеся.

Пошук залежить від доступності UDP Multicast. Точка доступу, гостьова Wi-Fi мережа, VLAN або ізоляція клієнтів можуть блокувати Multicast чи прямі TCP-з'єднання.

### Ручне підключення

1. На вузлі, який створює сесію, запустіть прослуховування та подивіться його `SessionId` і TCP-порт.
2. Дізнайтеся локальну IPv4-адресу цього пристрою.
3. На іншому вузлі відкрийте **Підключитися вручну** та введіть `SessionId`, IP-адресу й TCP-порт.
4. Натисніть **Приєднатися за IP**.

Для ручного підключення TCP-порт має бути доступний у локальній мережі та дозволений брандмауером. Адреса `127.0.0.1` вказує на цей самий пристрій, а не на інший комп'ютер чи телефон.

## Android

Android-проєкт налаштований на `net10.0-android36.0` і `android-arm64`; мінімальна версія — Android API 23. Команда створення APK наведена в розділі **Збирання**.
