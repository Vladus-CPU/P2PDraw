# P2PDraw

Кросплатформна P2P-система спільного векторного малювання в локальній мережі. Кілька пристроїв можуть працювати з одним документом без центрального сервера: зміни передаються між вузлами як операції над векторними об'єктами.

Застосунок має спільне ядро та інтерфейс на Avalonia UI, працює на Windows і має Android-збірку.

## Можливості

- Спільне малювання між кількома вузлами в одній локальній мережі.
- Пошук доступних сесій через UDP Multicast або підключення вручну за IP-адресою та TCP-портом.
- Малювання довільних штрихів, ліній, прямокутників та еліпсів.
- Вибір, переміщення, зміна розміру, дублювання та видалення об'єктів.
- Шари: створення, перейменування, зміна порядку, очищення та видалення. Видимість і блокування шарів керуються локально на пристрої.
- Скасування та повторення дій (Undo/Redo).
- Масштабування й переміщення полотна, сенсорне керування.
- Збереження та відкриття проєктів `.p2pdraw`, експорт у SVG та PNG.
- Окремий консольний симулятор для перевірки взаємодії вузлів без графічного інтерфейсу.

## Як влаштована система

P2PDraw використовує топологію **Full Mesh**: кожен вузол встановлює TCP-з'єднання з іншими учасниками тієї самої сесії. Центральний сервер для зберігання документа або пересилання операцій не використовується. Кожен вузол має власний екземпляр документа та журнал отриманих операцій.

### Виявлення вузлів

Для пошуку учасників у локальній мережі використовується UDP Multicast:

- вузол періодично надсилає оголошення з `PeerId`, `SessionId`, TCP-портом і версією протоколу;
- інші вузли перевіряють оголошення та показують доступні сесії;
- адреса вузла визначається за адресою відправника UDP-пакета;
- за відсутності Multicast можна скористатися ручним TCP-підключенням за IP-адресою та портом.

Параметри реалізації: група Multicast `239.255.51.10`, UDP-порт `5100`, період оголошення - 2 секунди. Записи про вузли, від яких немає оголошень понад 8 секунд, прибираються зі списку.

### Встановлення TCP-з'єднання

Після виявлення або ручного введення адреси вузли встановлюють TCP-з'єднання. Під час початкового обміну перевіряються:

- `PeerId` - ідентифікатор вузла;
- `SessionId` - ідентифікатор спільної сесії;
- `ProtocolVersion` - версія мережевого протоколу.

Після обміну службовими повідомленнями вузли передають операції та виконують початкову синхронізацію. Інформація про відомі адреси учасників допомагає формувати mesh-з'єднання. Для одночасних зустрічних підключень використовується детерміноване правило вибору напрямку, щоб не залишати два паралельні TCP-з'єднання між тією самою парою вузлів.

### Передавання повідомлень

Мережеві повідомлення серіалізуються в JSON. Щоб TCP-потік можна було розділити на окремі повідомлення, кожен пакет має 4-байтовий заголовок із довжиною тіла у Big Endian, після якого передаються UTF-8 байти JSON.

Максимальний розмір одного мережевого повідомлення - **4 MiB**. Для некоректних, неповних або завеликих повідомлень передбачена перевірка. Довгі штрихи розбиваються на менші операції додавання точок; одна операція `StrokeAppend` містить не більше 1024 точок.

### Модель операцій і синхронізація

Малюнок не передається як растрове зображення під час кожного редагування. Замість цього вузли обмінюються операціями над векторним документом: початок/продовження/завершення штриха, створення фігури, переміщення, зміна розміру, видалення та операції над шарами.

Кожна операція має мітку, що містить:

- `OperationId` - унікальний ідентифікатор операції;
- `PeerId` - автора операції;
- `SequenceNumber` - порядковий номер операції цього вузла;
- `LamportTime` - логічний час.

Журнал операцій (`OperationLog`) зберігає операції, запобігає повторному додаванню вже відомих `OperationId` та перевіряє унікальність пари `PeerId + SequenceNumber`.

Логічний годинник Лампорта оновлюється під час створення та отримання операцій. Для детермінованого порядку використовується порівняння `LamportTime`, потім `PeerId`, а за потреби - `OperationId`. Це задає узгоджений порядок обробки, але саме по собі не означає використання фізичного часу чи гарантування причинного порядку всіх подій.

### Видалення, конфлікти та відновлення

Видалені ідентифікатори об'єктів зберігаються як **tombstones**. Тому запізніла операція створення або зміни не повинна відновити об'єкт із тим самим ідентифікатором. Ідентифікатори об'єктів не використовуються повторно.

Операції над одним об'єктом відтворюються в детермінованому порядку. Для переміщення та зміни розміру зберігається відповідна остання за міткою операція. Очищення полотна формує операцію для об'єктів, відомих вузлу в момент очищення; це не є командою видалення майбутніх або ще невідомих об'єктів.

Під час синхронізації вузли обмінюються ідентифікаторами відомих операцій. Вузол може надіслати відсутні операції або Snapshot. Snapshot містить стан документа, журнал операцій, tombstones, шари та інформацію про незавершені штрихи. Отриманий Snapshot перевіряється й об'єднується з локальним журналом. Після втрати з'єднання вузол може продовжувати локальне редагування; для відомих адрес передбачено повторне підключення та подальший обмін відсутніми операціями.

> Реалізація використовує окремі механізми журналу операцій, логічного часу та tombstones. Її не слід називати повною реалізацією конкретного CRDT-алгоритму або алгоритму глобального знімка Chandy-Lamport.

## Структура рішення

Рішення розділене на окремі проєкти за відповідальністю:

```text
P2PDraw/
├── P2PDraw.sln
├── global.json
├── src/
│   ├── P2PDraw.Core/
│   │   ├── Models/          # Документ, штрихи, фігури та шари
│   │   ├── Operations/      # Типи операцій і журнал
│   │   ├── Sync/            # SyncEngine, Lamport Clock, Snapshot
│   │   ├── Storage/         # Формат файлу проєкту
│   │   └── Export/          # Векторний експорт SVG
│   ├── P2PDraw.Networking/
│   │   ├── Discovery/       # UDP Multicast Discovery
│   │   ├── Protocol/        # Повідомлення та TCP framing
│   │   └── Transport/       # TCP-з'єднання між вузлами
│   ├── P2PDraw.App/
│   │   ├── Controls/        # Полотно
│   │   ├── Documents/       # Відкриття та збереження файлів
│   │   ├── Editing/         # Undo/Redo та дублювання
│   │   ├── Export/          # Рендеринг і PNG
│   │   ├── Interaction/     # Введення, геометрія, масштаб і панорамування
│   │   ├── Session/         # Сесія та керування з'єднаннями
│   │   ├── Styles/          # Спільні стилі інтерфейсу
│   │   ├── ViewModels/      # Стан редактора, сесії та шарів
│   │   └── Views/           # Avalonia-подання
│   ├── P2PDraw.Desktop/     # Точка входу Windows/Desktop
│   ├── P2PDraw.Android/     # Android Activity та точка входу
│   └── P2PDraw.Simulator/   # Консольний вузол для мережевих сценаріїв
└── tests/
    └── P2PDraw.Tests/
        ├── App/
        ├── Core/
        ├── Integration/
        └── Networking/
```

### Призначення проєктів

| Проєкт | Відповідальність |
|---|---|
| `P2PDraw.Core` | Незалежна від UI модель документа, операції, журнал, логічний годинник і синхронізація |
| `P2PDraw.Networking` | UDP Discovery, TCP transport, мережеві повідомлення та framing |
| `P2PDraw.App` | Спільний інтерфейс Avalonia, ViewModel, взаємодія з полотном, шари та файли |
| `P2PDraw.Desktop` | Запуск настільної версії |
| `P2PDraw.Android` | Запуск Android-версії |
| `P2PDraw.Simulator` | Консольне керування вузлом для тестування обміну |
| `P2PDraw.Tests` | Модульні, UI-, мережеві та інтеграційні тести |

- **C# / .NET 10**

## Вимоги

Для збирання Desktop-версії:

- .NET SDK 10;
- Windows, Linux або macOS із підтримуваним .NET середовищем.

Для Android-збірки додатково потрібні:

## Отримання проєкту

Клонуйте репозиторій та перейдіть до його каталогу:

```powershell
git clone https://github.com/Vladus-CPU/P2PDraw.git
Set-Location P2PDraw
```

Відновіть NuGet-залежності:

```powershell
dotnet restore P2PDraw.sln
```

## Запуск Windows-версії

Запуск графічного редактора з кореня репозиторію:

```powershell
dotnet build src/P2PDraw.Desktop/P2PDraw.Desktop.csproj -c Release
dotnet run --project src/P2PDraw.Desktop/P2PDraw.Desktop.csproj -c Release --no-build
```

Для запуску двох незалежних екземплярів відкрийте два термінали й виконайте команду в кожному. У першому екземплярі створіть сесію, у другому знайдіть її та приєднайтеся. Обидва пристрої мають бути доступні в одній локальній мережі.

## Підключення учасників

### Через пошук сесій

1. Запустіть P2PDraw на обох пристроях.
2. Переконайтеся, що вони підключені до однієї локальної мережі.
3. На першому пристрої відкрийте панель «Сесія» та створіть сесію.
4. На другому пристрої відкрийте «Сесія» та запустіть пошук.
5. Виберіть знайдену сесію та приєднайтеся.

Пошук залежить від доступності UDP Multicast у локальній мережі. Деякі точки доступу, гостьові Wi-Fi мережі, VLAN або налаштування ізоляції клієнтів можуть блокувати Multicast чи прямі TCP-з'єднання.

### Ручне підключення

Якщо пошук не працює:

1. На пристрої, який створює сесію, запустіть прослуховування.
2. Дізнайтеся його локальну IPv4-адресу та TCP-порт, який показує застосунок.
3. На іншому пристрої відкрийте ручне підключення.
4. Введіть IP-адресу та TCP-порт вузла, до якого потрібно приєднатися.
5. Переконайтеся, що обидва пристрої використовують той самий `SessionId`.

Для ручного підключення також потрібні доступність TCP-порту та дозвіл у брандмауері. Адреса `127.0.0.1` означає поточний пристрій, а не інший комп'ютер чи телефон.

## Android

Android-проєкт налаштований на:

- Target Framework: `net10.0-android36.0`;
- Runtime Identifier: `android-arm64`;
- мінімальну версію Android API 23.

Завантажити потрібні Android-компоненти, зібрати APK, встановити його на підключений телефон і запустити:

```powershell
$env:AndroidSdkDirectory = "$env:LOCALAPPDATA\Android\Sdk"
$env:JavaSdkDirectory = "$env:LOCALAPPDATA\Android\Jdk"
dotnet workload install android
dotnet build src/P2PDraw.Android/P2PDraw.Android.csproj -t:InstallAndroidDependencies -f net10.0-android36.0 -p:AcceptAndroidSDKLicenses=True
dotnet publish src/P2PDraw.Android/P2PDraw.Android.csproj -c Release -f net10.0-android36.0
& "$env:AndroidSdkDirectory\platform-tools\adb.exe" install -r "src\P2PDraw.Android\bin\Release\net10.0-android36.0\android-arm64\publish\org.p2pdraw.app-Signed.apk"
& "$env:AndroidSdkDirectory\platform-tools\adb.exe" shell monkey -p org.p2pdraw.app 1
```

Телефон має бути підключений із дозволеним USB debugging. Під час першого підключення підтвердьте налагодження на телефоні.

Фізичне тестування на конкретній моделі телефону слід проводити окремо: успішна компіляція APK не замінює перевірку на реальному пристрої.

## Консольний симулятор

`P2PDraw.Simulator` запускає мережевий вузол без графічного інтерфейсу. Він приймає TCP-порт, GUID сесії та необов'язковий GUID вузла:

```powershell
dotnet run --project src/P2PDraw.Simulator -- 5101 11111111-1111-1111-1111-111111111111
```

У другому терміналі запустіть інший вузол з тим самим `SessionId`, але іншим портом:

```powershell
dotnet run --project src/P2PDraw.Simulator -- 5102 11111111-1111-1111-1111-111111111111
```

Після запуску вузли повідомлять про готовність у JSON-форматі. У консолі доступні команди:

| Команда | Призначення |
|---|---|
| `connect <ip> <port>` | Підключитися до іншого вузла |
| `begin` | Почати штрих і отримати його ID |
| `append <stroke-id> <x> <y> [x y ...]` | Додати точки до штриха |
| `end <stroke-id>` | Завершити штрих |
| `draw <x1> <y1> <x2> <y2>` | Створити простий штрих із двох точок |
| `shape <line\|rectangle\|ellipse> <x1> <y1> <x2> <y2>` | Створити векторну фігуру |
| `move <object-id> <offset-x> <offset-y>` | Перемістити об'єкт |
| `remove <object-id>` | Видалити об'єкт |
| `clear` | Очистити відомі вузлу об'єкти |
| `duplicate` | Повторно надіслати журнал операцій |
| `disconnect` | Відключити поточні з'єднання вручну |
| `drop` | Розірвати з'єднання з можливістю автоматичного перепідключення |
| `state` | Вивести короткий стан вузла |
| `snapshot` | Вивести Snapshot |
| `log` | Вивести журнал операцій |
| `help` | Показати список команд |
| `quit` | Завершити симулятор |

Для підключення другого вузла до першого введіть у консолі другого вузла:

```text
connect 127.0.0.1 5101
```

## Тестування

Усі автоматизовані тести розташовані в `tests/P2PDraw.Tests` та згруповані за напрямами:

- `Core` - модель документа, операції, Lamport Clock, журнал, шари, Snapshot, збереження та експорт;
- `Networking` - TCP, UDP Discovery, framing, валідація повідомлень, mesh-з'єднання та перепідключення;
- `App` - взаємодія з полотном, компонування, шари, історія редагування та файлові дії;
- `Integration` - сценарії взаємодії окремих процесів і вузлів.

Запуск тестів:

```powershell
dotnet test tests/P2PDraw.Tests/P2PDraw.Tests.csproj -c Release
```

Повна збірка рішення:

```powershell
dotnet build P2PDraw.sln
```

## Формати документів

| Формат | Призначення |
|---|---|
| `.p2pdraw` | Власний формат проєкту на основі JSON. Містить Snapshot, журнал операцій, об'єкти, шари та дані для відновлення стану |
| `.svg` | Векторний експорт штрихів, фігур і шарів |
| `.png` | Растровий експорт поточного вмісту документа |

Файл `.p2pdraw` має версію формату та обмеження розміру **32 MiB**. Мережеві повідомлення мають окреме обмеження - **4 MiB** на одне повідомлення. Для PNG діють обмеження до 4096 пікселів на сторону та до 16 мільйонів пікселів загалом; для більших зображень передбачено використання SVG.

## Відомі обмеження

- Система розрахована на роботу в локальній мережі. NAT traversal, підключення через Інтернет і центральний relay-сервер не реалізовані.
- Виявлення через UDP Multicast залежить від конфігурації мережі. Для таких випадків передбачене ручне TCP-підключення.
- Учасники повинні працювати з однаковим `SessionId` і сумісною версією протоколу.
- Видимість і блокування шарів є локальними налаштуваннями інтерфейсу пристрою, а не спільними операціями документа.
- Відновлення стану документа після примусового завершення процесу Android не слід вважати автоматичним: для збереження роботи використовуйте файл `.p2pdraw`.
- Android-збірка орієнтована на ARM64. Підтримка інших Android ABI у поточному проєкті не налаштована.
- Успішна збірка Android не підтверджує сумісність із кожною моделлю пристрою; потрібне окреме тестування на фізичному телефоні.
